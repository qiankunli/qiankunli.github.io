## 前言

人的直觉 “根据文字，一次前向计算直接生成图片”

$$
\text{Text}
\xrightarrow{\text{Encoder}}
c
\xrightarrow{\text{生成网络}}
\text{Image}
$$

比如一张 $256\times256$ 的 RGB 图片，本质上就是一个 `256 × 256 × 3` 的数组。NN 完全可以输出这么多数字（文字接龙 ==> 像素接龙/patch接龙），就是接龙次数有点多，图片越高清推理次数越多，1024 * 1024的图片要100w次，《红楼梦》也就是9xw字。使用 patch 或压缩后的 image token 可以缩短序列，但仍有串行依赖。因此，一条重要路线是 Non-autoregressive Generation（NAR）：平行运算/一次生成所有基本单位。

```
同一个条件可以对应多种合理结果
          ↓
需要学习分布，并能从中采样
          ↓
VAE：能否通过潜变量表达不同结果？
GAN：能否让判别器教会生成器？
Diffusion：能否把生成转化成可监督的去噪任务？
Flow Matching：能否直接监督从噪声到数据的变化速度？
```

## 为什么一个输入会有多个合理答案

还有一个问题在于：**拿什么作为训练目标？** “猫的图片”没有唯一正确答案（所以说一图胜千言）。同一句“生成猫的图片”，可以对应：

- 正面的白猫。
- 侧面的橘猫。
- 躺着的黑猫。
- 不同背景、姿势、光照的猫。

如果让确定性网络 $f_\theta(c)$ 根据文字直接输出一张图片，这属于 Point Estimation（点估计）。采用像素误差训练：$L=\|f_\theta(c)-x_{\text{真实图片}}\|^2$，模型可能被要求：对相同或相似的文字输入，同时接近很多差异很大的图片。平方误差倾向于条件平均。**不同猫的轮廓、位置、颜色平均起来，可能只剩一团模糊的影子。**

![](/public/upload/machine/vae.png)

对相同条件下的多种真实图片求期望时，理想最优预测是 Conditional Mean（条件均值）：

$$
f^*(c)=\mathbb E[X\mid c]
$$

## 从预测一个值到学习分布

Generative Models (GMs) aim to learn the stochastic process underlying the very generation of the data collected, 通常通过拟合一个概率分布来近似未知的数据分布，并从中采样产生新的结果。对于条件生成，目标是让模型的 Conditional Distribution（条件分布）$p_\theta(x\mid c)$ 接近数据分布 $p_{\mathrm{data}}(x\mid c)$：给定条件 $c$，哪些结果 $x$ 合理，各有多常见。

LLM 在每一个生成位置输出下一 token 的 Categorical Distribution（类别分布）。由于单个 token 的候选集合是有限词表，这个分布可以用长度为 vocabulary size 的概率向量表示；完整回答的分布则由逐步条件概率共同确定。
$$
\text{hidden state }h
\xrightarrow{\text{Linear}}
\text{logits}
\xrightarrow{\text{Softmax}}
\text{Token 概率}
\xrightarrow{\text{采样}}
\text{Token}
$$

### 连续输出：用概率分布描述

机器人的动作通常处于连续、多维空间；如果要学习动作分布，可以用连续概率分布来描述。以一维动作的单高斯策略为例，nn不直接输出“移动 2 厘米”，而是输出一个（单）**高斯分布（正态分布）**的两个参数：$\mu=2,\qquad \sigma=0.2 $，表示：$a\sim\mathcal N(2,\;0.2^2)$，直觉就是：大多数动作在 2 厘米附近，偏离得越远，出现的可能性越小。

$$
\text{hidden state }h
\xrightarrow{\text{Output Head}}
(\mu,\sigma)
\xrightarrow{\text{确定分布}}
\mathcal N(\mu,\sigma^2)
\xrightarrow{\text{采样}}
\text{动作 }a
$$

### 从单峰到多峰

单高斯只有一个峰。如果要表达之前的“向左绕、向右绕都合理，中间不合理”，就需要能表达多峰分布的模型，例如 Gaussian mixture。但描述分布不一定要直接输出一组分布参数。另一种方法是学习一个生成过程：从容易采样的 noise 出发，根据当前 observation 将它变换成合理动作。只要不同 noise 经过变换后形成的整体分布接近示范动作分布，我们就能通过运行这个过程生成动作。Diffusion 和 Flow Matching 都可以用于构建这样的生成过程。

这是一种通过生成过程表示分布的思路。把整个过程记作：

$$
z\sim p_{\mathrm{noise}},
\qquad
x=G_\theta(z,c)
$$

这里 $z$ 包含生成所需的随机性，$G_\theta$ 可以是一次网络调用，也可以是多步生成过程。大量随机输入经过它变换后，输出形成的分布就是模型的 Induced Distribution（诱导分布）。

因此，“能够采样”与“能够计算样本的概率或密度”是两种不同能力。GAN 是典型的 Implicit Generative Model（隐式生成模型）：容易生成样本，但通常不直接提供样本的 likelihood。Diffusion / Flow 也可以通过生成过程理解，但其密度计算能力要看具体模型和方法，不能一概视为不可计算。

“学习分布”，就是让模型学到：左绕、右绕都是合理结果，应该有较高概率；撞上去不合理，应该有较低概率。学到分布之后，机器人最终需要的是一段具体的动作，不能执行“一组可能性”。所以还需要 “从中采样”：按照学到的概率规律，产生一个具体的 Action。这一次可能生成左绕，下一次可能生成右绕。采样带有随机性，但受到当前场景和所学分布的约束。

## 生成顺序：AR 与 NAR

生成一个复杂对象时，各个部分应该按什么顺序产生，才能既快又协调？
1. AR(autoregressive generation)：每轮只生成下一个单位。后面生成的内容，能看到前面已经选了什么，每次做新选择时，前面的选择已经确定，可以据此保持一致。代价是串行：第二个输出要等第一个，第三个要等第二个。
    ![](/public/upload/machine/image_ar.png)
2. NAR( non-autoregressive generation)：不按固定顺序逐个生成输出单位，而是并行预测或更新多个位置。完整结果可以一次产生，也可以经过多轮修订。它需要解决的问题是：各位置怎样作出相互协调的选择？如果只根据文字条件独立采样每个位置，局部合理的选择可能拼成不合理的整体。。
    ![](/public/upload/machine/image_nar.png)
    ![](/public/upload/machine/multi_modality_problem.png)


数学上，需要学习的是各位置的 Joint Distribution（联合分布）。AR 通过条件概率链显式表达依赖：

$$
p(x_1,\ldots,x_N\mid c)
=
\prod_{i=1}^{N}p(x_i\mid x_{<i},c)
$$

*如果采用最简单的条件独立假设，则变成：*

$$
p(x_1,\ldots,x_N\mid c)
\approx
\prod_{i=1}^{N}p(x_i\mid c)
$$

后者省略了输出之间的依赖。并行计算本身并不要求这种独立假设；共享潜变量、联合生成网络和多轮修订，都可以帮助建立位置之间的关联。

### NAR 优化路线

1. 补充共同条件，这样不同位置不是各自决定画什么，而是共同实现同一个方案。
    ![](/public/upload/machine/nar_c.png)
    
    但不能指望用户把图片每个细节都描述出来。因此，模型可以引入一个共享潜变量：z，同一个z影响整个输出，因此各位置可以产生相关、协调的结果。
    ![](/public/upload/machine/nar_z.png)
2. 先生成精简表示，再（并行）展开细节。精简表示不一定是一张小图片，也不一定是人能读懂的描述。 它可以是学习得到的编码。
    ![](/public/upload/machine/ar_nar.png)
3. 不要一次到位，改为多轮并行修订。存在顺序依赖，但不是 LLM 那种“逐 Token 接龙”。
    ![](/public/upload/machine/multi_nar.png)
    1. 由小图到大图，先形成低分辨率结果，再逐步增加细节
        ![](/public/upload/machine/nar_small2big.png)
    2. Diffusion，从高噪声状态开始，逐步生成低噪声结果
        ![](/public/upload/machine/nar_blurry2clear.png)

## GAN：通过对抗训练学习生成分布

那就加随机数，让它每次生成不同的猫？可以改成：

$$
x=G_\theta(c,z),
\qquad z\sim\mathcal N(0,I)
$$

- $c$：规定“要生成猫”。
- $z$：让每次生成可以不同。noise
- $G_\theta$：一次前向计算生成图片。

**条件 GAN 就采用这样的路线**。不过，单纯加上随机输入还不够：训练方法必须让网络真正利用它，学会多种合理结果，因此还需要合适的生成式训练目标，例如对抗训练。

## Diffusion：通过逐步去噪生成样本

Diffusion 换了一种训练与生成方式，它没有要求网络一次完成：
文字 + 随机数 → 一整张清晰图片。而是让同一个网络反复解决：当前带噪内容 + 文字条件 + 噪声等级 → 这一步的噪声预测。再由采样器逐步更新图片。这带来一个很实用的训练机制：用真实图片加已知噪声，就能自动构造大量训练题，并用噪声预测误差训练。但代价也明确：通常需要多次调用网络，推理比单次生成更费计算。

![](/public/upload/machine/diffusion_model_infer.png)

把生成过程从 $\text{文字}\xrightarrow{\text{NN}}\text{猫的图片}$ 拆成很多个更小的步骤： 按照“a cat in the snow”这个要求，眼前这张带噪图片，下一步应该怎样调整？重复这个过程。随机噪声就是生成多样性的一个来源，文字约束“哪些结果符合要求”，同样的文字条件下，从不同噪声出发，通常会生成不同的图片。噪声里并没有预先藏着一只猫，把这些随机起点逐步变成符合文字要求的图片，是模型从训练数据中学到的能力。PS：把文生图 ==> “command + 图”生图。

![](/public/upload/machine/diffusion_model_train.png)

类比教一个人整理房间，老师先收集很多合理的房间布局，然后按某种规则随机挪动物品：`合理布局 → 稍微弄乱 → 更乱 → 非常乱`，训练时，随机挑一个混乱程度，把房间交给学生，并告诉他“被打乱到了什么程度”。学生学习：从当前状态，怎样朝更合理的布局调整一步。 注意，不是每次都让学生从头整理到尾，而是反复练习不同房间、不同程度的“局部整理”。使用时，从一个按约定随机摆放的房间开始，反复调用学到的调整方法：

```
随机摆放
  → 调整一步
  → 根据新的摆放状态再调整
  → ……
  → 形成一个合理布局
```
最后不必恢复成训练中某一间房的布局，而是生成一种符合所学规律的新布局。不同初始摆放，也可以形成不同的合理结果。

### 生成过程示例

假设有一万张猫的图片，我们希望模型学到的不是“记住这一万张图片”，而是猫图片的共同规律，使它能生成新的、合理的猫图片。

```
condition = text_encoder("一只橘猫坐在窗边")
x = random_noise()

for k in reversed(noise_levels):
    predicted_noise = denoiser(x, k, condition)
    x = sampler_step(x, predicted_noise, k)

image = x
```

这里要区分 Denoiser（去噪网络）和 Sampler（采样器）：`denoiser` 输出当前噪声的预测，`sampler_step` 根据预测、噪声日程和具体更新公式，计算下一步状态。网络输出的预测并不直接等于下一张图片；网络与采样器共同组成完整生成过程。实际模型也可以预测干净样本或 velocity，噪声预测只是这里采用的一种 Parameterization（参数化方式）。

## Flow Matching：通过 velocity regression 学习生成过程

Mapping Gaussian noise to a bimodal distribution. 假设收集了很多数字，大部分聚集在 -2 和 +2 附近，中间比较少，这就是一种“双峰分布”。希望模型学会生成新的数字，而且生成很多次之后，也呈现这种规律。但电脑容易产生的是高斯随机数：很多数集中在 0 附近，离 0 越远越少。于是问题变成：

```
容易生成的随机数
       ↓ 某种变换
符合训练数据规律的数字
```

图片、机器人动作也是类似的，只不过一个样本包含很多数字：
- 一个数字：一维。
- 一张图片：很多像素组成的向量。
- 一段机器人动作：多步关节指令组成的向量。
Flow matching is a technique to learn how to transport samples from one distribution to another. For example we could learn how to transport samples from a simple distribution we can easily sample from (e.g. Gaussian noise) to a complex distribution (e.g. images, videos, robot actions, etc.).

没有随机输入，直接回归动作：相同条件通常只有一个输出，引入随机变量：让同一条件下能够产生不同答案，随机变量提供多样性的来源，训练负责把这种多样性组织成合理的动作分布。

### 模型预测什么：time-dependent vector field

模型学习的是什么？可以把 noise 中的每个样本想象成一个点。我们希望这些点经过移动，最终形成训练数据的分布。模型要学习的是一个 **time-dependent vector field**：给定一个点当前的位置和生成进度，告诉它应该往哪个方向移动，以及移动多快。用公式表示，模型的输入和输出是：

$$
\hat u_t = v_\theta(x_t,t)
$$

其中，$x_t$ 是当前样本，$t$ 是生成进度（The step $t$ is a value between 0 and 1 that describes the progress of the sample $x_t$ along the flow path from the noise distribution to the target distribution. ），$\theta$ 是模型参数。输出与样本维度相同，表示样本每个分量的变化方向与速度。**Flow** 描述样本随着时间连续移动形成的变换；**Matching** 则对应训练时让模型预测的 vector field 匹配目标 vector field。

生成时，从随机噪声 $x(0)$ 出发，求解由速度场定义的 Ordinary Differential Equation（ODE，常微分方程）：

$$
\frac{dx(t)}{dt}=v_\theta(x(t),t),
\qquad
x(0)\sim\mathcal N(0,I)
$$

Numerical Solver（数值求解器）把连续运动近似成有限次更新。例如最简单的 Euler Method（欧拉法）：

$$
x(t+\Delta t)
\approx
x(t)+\Delta t\,v_\theta(x(t),t)
$$

网络负责预测速度，求解器负责推进状态。给定初始噪声和求解设置，这条生成路径可以是确定的；不同初始噪声仍然能够产生不同结果。本文统一采用 $t=0$ 为噪声端、$t=1$ 为数据端。

想象从上方看一条河，在水面各处画箭头：
- 箭头方向：这里的水往哪里流。
- 箭头长度：这里的水流有多快。
- 不同位置的箭头可以不同：河中央快，岸边慢，转弯处方向变化。
这整片“每个位置对应一个流动方向和速度”的分布，就是ector field。把一片树叶放进河里，它的运动过程是：
```
树叶在位置 A → 根据 A 处的水流，移动一小段
来到位置 B   → 根据 B 处的水流，再移动一小段
来到位置 C   → 根据 C 处的水流，继续移动
```
为什么要多步计算?A 处的水流方向，只告诉你树叶此刻怎么动，不能直接告诉你最终会漂到哪里。对应到 Flow Matching：

| 河流中的例子 | Flow Matching |
|---|---|
| 树叶当前的位置 | 当前正在生成的动作矩阵 $X$ |
| 初始放入树叶的位置 | 随机噪声矩阵 |
| 当前位置的水流方向与速度 | 模型预测的 velocity |
| 随水流移动一小段 | $X_{\text{new}}=X+\Delta t\,v$ |
| 树叶漂出的路径 | 从噪声到动作的生成路径 |

另外，河流可以随时间涨落，所以同一个位置在不同时间，水流也可能不同。这对应模型既要看当前矩阵 $X$，也要看生成进度 $t$。模型学的是水流的 vector field：
1. 直接预测终点：输入树叶起点 → 输出最终位置。
2. Flow Matching：输入树叶当前位置、时间和条件 → 输出此刻应该往哪里、以多快的速度移动。

### 构造路径与目标速度

模型要预测什么，训练时就需要提供相应的目标值。我们需要将这些样本转化为与模型预测目标相对应的监督信号：构造从 noise 到真实样本的路径，并计算沿途的目标速度。一种简单做法是：随机抽取一个 noise 样本 $x_0$ 和一个真实数据样本 $x_1$，在两者之间构造一条直线路径：

$$
x_t=(1-t)x_0+t x_1,\qquad t\in[0,1]
$$

沿着这条路径匀速移动，所需的目标速度就是：

$$
u=x_1-x_0
$$

例如，抽到的 noise 是 0.3，真实数据是 2.1，那么在 $t=0.5$ 时，中间位置是 1.2，目标速度是 1.8。

### 训练步骤与损失函数

一次训练可以概括为：

1. 从数据集中抽取真实样本 $x_1$。
2. 从预先选定的分布中抽取 noise $x_0$，例如标准 Gaussian distribution。
3. 在 0 到 1 之间随机抽取一个 $t$，直接算出 $x_t$。
4. 让模型根据 $x_t$ 和 $t$ 预测速度。
5. 用预测速度与 $x_1-x_0$ 的误差更新模型。

对应的训练目标是：

$$
\mathcal L(\theta)
=
\mathbb E_{x_0,x_1,t}
\left[
\left\|v_\theta(x_t,t)-(x_1-x_0)\right\|^2
\right]
$$

**真实样本 $x_1$ 用来构造训练输入和监督目标，不会作为答案直接提供给模型。** 模型通过大量样本，学习在不同位置、不同生成进度下应该如何移动。这是 **Conditional Flow Matching** 的一种简化形式。训练时可以直接计算随机时刻的中间样本，不需要先完整模拟从 noise 到 data 的整个过程，因此[论文 §3–4](https://arxiv.org/html/2210.02747v2)称这种训练方式为 **simulation-free**。

### *动作矩阵示例：训练与推理*

Flow Matching 训练一个模型，让它知道：给定当前这份“尚未生成好的动作矩阵”，下一小步应该怎样修改它。它学习的是修改的方向和速度；推理时反复应用这些修改，得到最终动作。我们希望生成一个 3 × 2 的矩阵，Flow Matching 从一个同样大小的随机噪声矩阵开始，例如：
```
X = [
    [ 0.80, -0.40],
    [-0.20,  0.90],
    [ 0.50, -0.70],
]
```
这个矩阵只是模型内部的生成起点，不会发给舵机执行。实际模型通常在归一化的动作空间工作，这里先省略单位变换。每一次调用 Action Expert
1. 输入包括：
  1. 当前矩阵 X
  2. 生成进度 s
  3. 条件 C：由任务文本、图像、身体状态等形成的特征
2. 输出也是一个 3 × 2 矩阵，记为 V，表示每个元素应如何变化： `Action Expert(X, s, C) → V`
3. 然后通过普通数值计算更新：`新矩阵 = 当前矩阵 + 步长 × V`。
4. 接着，把更新后的矩阵再次交给同一个模型，重新预测变化方向。**每一轮都处理整个动作块**，不需要先生成关节 1 的 Token，才能生成关节 2 的 Token。
假设分成 10 次更新，步长就是 0.1。这 10 次更新全部发生在生成过程中，不是让机器人先执行噪声动作，再逐渐执行更好的动作。模型完成生成后，Runtime 才按机器人控制时间执行动作矩阵。

训练时我们有专家示范，因此知道某个任务、某组观测条件下，对应的真实动作矩阵 A。最简单的一种训练构造是：随机生成噪声矩阵 `ε`，然后在噪声与真实动作之间连一条直线：$X_s=(1-s)\varepsilon+sA$，这个公式就是按比例混合两个矩阵：

```text
s = 0.0：100% 噪声
s = 0.5：50% 噪声 + 50% 真实动作
s = 1.0：100% 真实动作
```
对于这条人为构造的直线，正确的变化速度很容易算：$V^*=A-\varepsilon=0.20-0.80=-0.60$，它的意思是：**生成进度每增加 1，这个数值应减少 0.60。**，继续用刚才的单个元素。随机选取 `s = 0.5`，得到中间值 `X_s = 0.50`。这次训练样本可以表达为：
```text
给模型的输入：
    条件 C
    当前值 X_s = 0.50
    生成进度 s = 0.50

要求模型预测：
    正确变化速度 V* = -0.60
```

假设模型预测为 `-0.40`，就用均方误差衡量预测与目标的差距：$\text{loss}=(-0.40-(-0.60))^2=0.04$，再通过反向传播更新模型参数。训练不断更换专家动作、随机噪声和生成进度，使模型学会在各种条件、各种中间状态下预测变化方向。真实动作 `A` 用来构造训练输入和监督标签，但不会作为额外答案直接传给模型。模型实际看到的是： `当前中间矩阵 + 生成进度 + 任务与观测条件`，它必须从大量训练样本中学习这些输入与变化方向之间的规律。

推理时，输入形式相同，只是从纯噪声开始，后续中间矩阵由模型自己的预测逐步产生。我们假设 Action Expert 已经训练好，现在给它：

```
任务：把机械臂移动到指定位置
观测：当前图像、关节位置等
```
目标是生成未来三个时刻、两个关节的动作，即一个 3 × 2 矩阵。推理时不知道正确答案是什么。
1. 先由 VLM 处理输入，得到条件特征 C，生成这一块动作的过程中，先保持 C 不变。后续拿到新的观测，可以再生成下一块动作。
2. 随机初始化一个动作矩阵，采样一个 3 × 2 的随机噪声矩阵，约定生成进度从 `s=0` 到 `s=1`。为方便手算，只进行两次更新，每次步长 `Δs=0.5`。实际使用的步数由模型配置决定。
    ```text
    X₀ = [
        [ 0.80, -0.40],
        [-0.20,  0.90],
        [ 0.50, -0.70],
    ]
    ```
3. 第一次调用：预测整个矩阵的变化速度。输入 `ActionExpert(X₀, s=0, C)`，假设模型输出：
    ```text
    V₀ = [
        [-0.60,  0.80],
        [ 0.40, -0.80],
        [-0.20,  1.00],
    ]
    ```
    通过 Euler 更新：`X₁ = X₀ + 0.5 × V₀`，逐元素计算：
    ```text
    X₁ = [
        [0.50, 0.00],
        [0.00, 0.50],
        [0.40, -0.20],
    ]
    ```
    现在生成进度到了 `s=0.5`。
2. 第二次调用：基于更新后的矩阵，重新预测**。输入`ActionExpert(X₁, s=0.5, C)`，再次更新：`X₂ = X₁ + 0.5 × V₁`，得到：
    ```text
    X₂ = [
        [0.10, 0.30],
        [0.15, 0.25],
        [0.20, 0.20],
    ]
    ```
    此时 `s=1`，生成结束，`X₂` 就是本次预测的 Action Chunk。

整个推理可以压缩成：

```text
C = 编码任务与观测
X = 随机噪声矩阵

从 s=0 推进到 s=1：
    V = 已训练模型(X, s, C)
    X = X + 步长 × V

返回 X 作为预测动作块
```

## 生成领域的强化学习

知道一个生成结果好不好，还不等于知道模型参数应该怎样修改。Reward 到 gradient 之间，需要一套具体机制。

|样本|	生成内容|	奖励|
|---|---|---|
|A|	三个红色杯子，画面清晰|	9|
|B|	三个红色杯子，画面略差|	7|
|C|	两个红色杯子|	3|
|D|	三个蓝色杯子|	1|

“图 A 得 9 分”只告诉我们结果好，没有告诉我们 DiT 中哪个参数应该增加、哪个参数应该减小。至少存在几种不同选择：

```
结果好
 ├─ 把它当作训练数据，多学几遍
 ├─ 对奖励求导，沿生成过程直接反传
 ├─ 计算生成概率，增加这类结果出现的机会
 └─ 修改去噪方向，使生成更接近偏好分布
```
这些选择最终都可能让奖励提高，但它们需要保存的数据、梯度经过的路径、能否使用黑盒奖励，很不一样。后面比较方法时，始终追踪三件事：奖励怎样进入 loss，梯度推动哪个输出，更新后生成分布为什么会改变。

| 路线 | 怎样把评价变成更新 |
|---|---|
| RWR / RFT | 高分图多学，低分图少学或过滤掉；继续做普通去噪训练 |
| Reward Backpropagation | 如果奖励和生成过程可微，直接沿“图像 → 奖励”的导数反传 |
| PPO / DDPO / GRPO | 用 Advantage 加权已采动作的 log-prob 梯度，调整这些动作的概率 |
| Diffusion-DPO | 用偏好对，让模型相对参考模型更偏向赢家 |
| DiffusionNFT | 把奖励转成正负反馈，围绕旧模型预测构造新的回归目标 |

## 小结

多步生成提供了一种实用的学习方式：通过可构造的局部监督信号，学会一个复杂的生成过程。 例如 Flow Matching 用路径上的目标速度监督模型，生成时再积分得到样本。这是训练与采样方式的选择，并不是多峰分布的数学要求。
| | 训练时让模型学什么 | 生成时怎么做 |
|---|---|---|
| **Diffusion** | 给真实图片加噪，学习如何去噪 | 从 noise 开始，反复用学到的去噪规则更新样本 |
| **Flow Matching** | 构造 noise 到数据的路径，学习沿途的速度 | 从 noise 开始，沿预测的速度场更新样本 |
Diffusion 通过学习去噪来获得生成能力；Flow Matching 通过学习样本**如何移动**来获得生成能力。 用一个不太准确的类比，把一块形状杂乱的泥坯，塑造成一个可爱、腿长的娃娃。假设当前泥坯脸太宽、腿太短：
1. Diffusion想的是：“符合要求的完整娃娃，脸应该这么窄、腿应该这么长”。
    ```
    观察当前泥坯
    → 预测一个符合要求的完整形状
    → 由采样规则决定这一轮怎样调整
    → 观察调整后的泥坯，再次预测
    → ……
    ```
2. flow matching 想的是：“此刻脸部应向内收，腿部应向外伸”
    ```
    观察当前泥坯与塑形进度
    → 预测各部位的变化方向和速度
    → 积分器据此调整一小步
    → 在新状态重新预测
    → ……
    ```
